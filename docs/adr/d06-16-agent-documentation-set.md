# D06-16: the M3 agent and operator documentation set

Status: accepted; amended 2026-09-25: the set is the union of every list the plan named, generated regions are rendered from the snippet renderers and the observation record with placeholders, every snippet is preceded by its client's observation status, and the metadata documents advertise no documentation URL.

**As accepted.** Documentation set produced with M3: `docs/agents/{claude-code,claude-desktop,cursor,vscode,windsurf,claude-ai,messages-api,custom-clients}.md`, `docs/agents/tools-reference.md` (generated from `packages/contracts/mcp/tools.schema.json`), `docs/agents/reading-iridium.md`, and `docs/ops/mcp-clients.md`.

**Amended 2026-09-25.** The M3 set is `docs/agents/{getting-started,reading-iridium,connectors,claude-code,claude-desktop,claude-ai,cursor,vscode,windsurf,messages-api,custom-clients}.md`, the generated `docs/agents/tools-reference.md`, and `docs/ops/{mcp-clients,oauth}.md`, filled from their M0 stubs. `getting-started.md` is the human setup path and links to `reading-iridium.md`, the only home of the agent-facing model: ids versus paths, revisions, freshness, pagination, `search_notes → get_note`, line-range paging and untrusted content.

One `pnpm gen` step, "agent documentation" (`scripts/generate-agent-docs.ts`, with pure helpers in `scripts/lib/agent-docs.ts`), runs immediately after the MCP tool export and before the desktop IPC step, so the order is OpenAPI export, Redocly lint, `openapi-typescript`, the Kysely diff, `tools.schema.json`, agent documentation, desktop IPC, the msw skeleton, database grants, non-goals and the acceptance map, with non-goals still immediately before the acceptance map, which stays last. The step writes `tools-reference.md` from the committed `packages/contracts/mcp/tools.schema.json`, and rewrites the generated regions `<!-- gen:snippet client=<id> -->…<!-- /gen:snippet -->` and `<!-- gen:client-status product=<id> -->…<!-- /gen:client-status -->` of every per-client page — the snippet regions from the pure renderers of `apps/server/src/mcp/snippets.ts`, the status regions from `apps/e2e/mcp-clients/versions.json` — failing on a page that lacks a region its client needs. `COMMITTED_ARTEFACTS` gains `tools-reference.md` and the `docs/agents` pages that carry generated regions, all drift-checked by `gen.drift.guard`.

The renderers are pure functions of `{origin, version, bridgePath, oauthEnabled}` and the client enum member, and `snippets.ts`'s only value import is `@iridium/contracts` (ARCH-30), so they can read no build information, package manifest or environment. The route passes the live origin and version and the literal `<bridge-path>`, which the client host substitutes; the generator renders only with the placeholders `<origin>`, `<version>` and `<bridge-path>`, so the generated Markdown is identical across releases and a version commit cannot turn `gen.drift.guard` red. As defence in depth, the generator fails when a snippet region contains the root `package.json` version `V` as a whole token: the pure `findVersionLeaks(text, V, maskedPins)` matches `(?<![\w.])V(?!\w|\.\d)` with `V` regex-escaped, after masking the pinned client versions `snippets.ts` exports, so a version followed by `.mjs` or ending a sentence is caught and a prefix of a longer version is not. Client-status regions are exempt, because their versions change only when an observation is recorded.

Every snippet region is immediately preceded by the client-status region of the `versions.json` row or rows its client maps to, and the generator fails a page where that neighbour is missing. The status reads "Observed with <product> <version> on <date> against Iridium <iridiumVersion> (<observedIn>)", "Not yet observed; due at M<n>. The configuration below follows the product's own documentation and may change when it is observed.", or "Not supported as written: <failure>; use <fallback>". A product not yet observed is therefore never published as bare instructions; that adjacent status is the accepted mitigation for configuration that must exist before it can be observed. `docs.agent-docs.guard` (guard project, `ci.yml › static`) proves the leak scan and the adjacency rule with poison cases, importing the same pure functions. Hand-written text outside the regions describes only observed behaviour, and hand-written product click paths come only from an observation: S9 at M3 for headless clients, and `docs/acceptance/mcp-gui-clients.md` and S15 before M4 exit for GUI clients and connector products.

The metadata documents advertise no documentation URL: `resource_documentation` (optional under RFC 9728) and `service_documentation` (optional under RFC 8414) are removed from the Protected Resource Metadata and the authorization-server metadata, because no route serves the agent documentation and a URL outside the deployment would be wrong for air-gapped sites and for every other release. The fields return only with a route, or an operator-configured URL, that serves the documentation, recorded as its own decision; `oauth.metadata.contract` asserts both are absent. Phasing: at M3 `getting-started.md` creates a token through REST (`POST /auth/sessions`, step-up, `POST /me/tokens`) and lists and revokes it with the CLI, `connectors.md` documents what Iridium controls and that M3 builds offer no browser sign-in (AG9), and `docs/ops/oauth.md` documents `iridium oauth clients list`, what an unverified dynamic registration means, and the doctor line for the sign-in surface; M4 adds Settings › Integrations and browser sign-in, and M7 adds the OAuth-clients console.

Both lists the plan carried were normative and written without reference to each other, so the union honours both. Generating snippets and status regions from `snippets.ts` and `versions.json` means the pages cannot disagree with what the server renders or with what was observed, and a documentation page serves every deployment and release, so concrete values in it would be wrong for almost every reader. Rejected: keeping `tools.md`; a second generator step for the tools reference; hand-copied snippet blocks; rendering regions with the live version; a substring leak test; a lookahead that refuses every following dot; one monolithic generated page; click paths written from vendor documentation without a status line; serving `docs/agents` from the server; an external documentation URL.
