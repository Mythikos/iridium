# D12-15: one spike register; spike timing and fallback references

Status: accepted; amended 2026-09-25: a spike that needs a milestone's surface runs at that milestone before its exit (S9 at M3, S15 at M4), and a failed spike's fallback is named by a pull request or a commit.

**As accepted.** §4.4 is the single spike register for the whole plan: it carries the same ids, the same `Runs at` assignments and the same `docs/spikes/S<nn>-<slug>.md` filenames as the register in `14-risks-and-open-questions.md`, including the three spikes that run at M1, M2 and M3 rather than M0, and no other section introduces a spike id. The "spikes closed" gate is the `docs.spikes.spec` test, not a manual read-through.

**Amended 2026-09-25 (spike timing and fallback references, shared with D14-11).** A spike that needs a milestone's surface runs at that milestone once the surface exists and before its exit. S9's `Runs at` is "M3 (before exit)" and S15's "M4 (before exit)" (AG9), identically in `12-milestones.md` §4.4 and in `14-risks-and-open-questions.md`, whose intros read "Ten spikes run at M0; four run at the milestone whose surface they need, before its exit: S10 at M1, S11 at M2, S9 at M3 and S15 at M4" — the four that replace the "three spikes that run at M1, M2 and M3" above. A failed spike names the pull request or the commit (`commit <sha>`) that executed its fallback; while main is worked without pull requests (owner instruction, 2026-09-19) that is the milestone commit, written in by the follow-up docs commit, because a commit cannot name itself. `docs.spikes.spec` needs no code change: it compares milestone numbers only and already accepts a commit reference.

A spike cannot observe a surface that does not exist: S9 configures clients from the M3 snippet route against a live OAuth endpoint, and S15 needs `/mcp/connect`, the consent page and a browser sign-in surface. "Before exit" keeps each a gate on the milestone that needs it (D14-11) without pretending it precedes the work. The guard, the spike template's README and 10's spike-register table already accept commit references, so the plan text was the stale party. Rejected: keeping "entry" and running a spike against a partial server.
