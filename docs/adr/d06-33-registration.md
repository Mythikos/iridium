# D06-33: dynamic client registration

Status: accepted; amended 2026-09-25: the route stays registered whenever `MCP_OAUTH_ENABLED` and a per-request gate applies the policy; registration is RFC 7591 JSON with the RFC's `grant_types` default and a `none`-only `token_endpoint_auth_method`; the ceiling counts active dynamic rows that never completed an authorization.

**As accepted.** Dynamic client registration is on by default, bounded by `OAUTH_DCR_PER_IP_PER_HOUR` 10, `OAUTH_MAX_UNUSED_CLIENTS` 1 000, a 7-day sweep of clients that never completed an authorization, a mandatory `application_type`, no secret for public clients, and an admin kill switch that also removes `registration_endpoint` from the metadata; a dynamically registered client is marked unverified everywhere it is shown. claude.ai performs automatic registration, so a default of off would make "the connectors work out of the box" untrue for any client that does not publish a Client ID Metadata Document — and that is the owner's answer, not a preference. The specification deprecates RFC 7591 but retains it for backwards compatibility, so Iridium prefers metadata documents and accepts registration under bounds rather than refusing it and shipping a connector that cannot connect.

**Amended 2026-09-25.**

- **The switch.** `POST /oauth/register` is registered whenever `MCP_OAUTH_ENABLED` is true, in every boot, so the route table and the served CSRF exemption set depend on that flag alone. The effective policy — `SettingsStore.effective().oauthPolicy.allowDynamicClientRegistration`, which combines the `OAUTH_ALLOW_DYNAMIC_CLIENT_REGISTRATION` floor with the administrator's value (AG12) — is read per request by `registrationPolicyGate`, a route-level `onRequest` hook declared first in the route's options in `oauth/register.ts`. It runs after the root hooks and before body parsing, the body limit, the media-type check, schema validation and the route's own limiter. While the policy is off the gate answers `404` with an empty body and `Cache-Control: no-store`, increments `iridium_oauth_registration_refused_total{reason='policy_disabled'}`, writes no row and consumes no DCR budget, whatever the body, and the authorization-server metadata omits `registration_endpoint` on every response rendered while it is off. With `MCP_OAUTH_ENABLED=false` the path is unregistered and the routing branch answers the identical bytes before any body work (D09-30 as amended).
- **The request.** `POST /oauth/register` takes and answers `application/json` (RFC 7591 §3.1), with RFC 7591 §3.2.2 errors; `/oauth/token`, `/oauth/revoke` and the consent `POST` stay form-urlencoded. Omitted `grant_types` default to RFC 7591 §2's `['authorization_code']`, stored and echoed, and a refresh token is issued only when `grant_types` include `refresh_token`; manual clients get both (D06-45). An omitted `token_endpoint_auth_method` is registered as `none` and returned in the `201` response (RFC 7591 §3.2.1); an explicit `none` is accepted; any other value is `400 invalid_client_metadata`, never silently replaced. `application_type` stays mandatory. An omitted `scope` means the client's registered scopes, and a present one must be a subset of them.
- **The consent page's duration line** follows the grant types: for a client whose `grant_types` include `refresh_token`, "This access refreshes automatically until you revoke it in Settings › Integrations."; otherwise "This application's access lasts <accessTokenTtlMinutes> minutes at a time; while you are signed in it can ask again without this page, until you revoke it in Settings › Integrations."
- **The ceiling and the sweep.** "Never authorized" is `first_authorized_at IS NULL` (D03-27). `OAUTH_MAX_UNUSED_CLIENTS` counts only rows with `registration_kind='dynamic'`, `status='active'` and `first_authorized_at IS NULL`, counted by `countUnusedDynamicClients(trx)` in `auth/oauth/clients.ts`, which owns `oauth_clients` persistence; `oauth/register.ts` only compares the count with the limit and refuses with `403 access_denied`. The sweep deletes `registration_kind = 'dynamic' AND first_authorized_at IS NULL AND status <> 'disabled'` rows `OAUTH_UNUSED_CLIENT_TTL_DAYS` after `created_at`. A CIMD row is created authorized, so it is never counted and never swept (D06-41).

06's own principle rules out a route table that is a function of a database row, and only an `onRequest` hook can answer before the body is looked at, so the policy-off and OAuth-off states cannot be told apart by any body. The authorization-server document is cached up to an hour, so a client can hold a stale `registration_endpoint`; a deterministic `404` byte-identical to the unregistered path's answer says what the metadata says. The RFC 7591 defaults grant no capability a client did not declare. Rejected: conditional registration, which ties the route table and the CSRF set to a policy row; a check in the handler, `preValidation` or `preHandler`, which would leak liveness through `400`/`413`/`415`/`422`; `403 access_denied` for the switch, which is reserved for the ceiling; defaulting to both grants; silently replacing an explicit `client_secret_basic`; a shared DCR/CIMD ceiling.

Verification: `oauth.dcr.integration` (the policy flipped through `PUT /admin/settings`: the `404` and the omitted `registration_endpoint` on the next request for valid, invalid, oversized, wrongly typed, empty and malformed bodies, and the same bytes with `MCP_OAUTH_ENABLED=false`; the `token_endpoint_auth_method` and `application_type` cases), `oauth.metadata.contract` and `oauth.sweep.integration`.
