# ARCH-30: the MCP module exposes only its snippet renderer

Status: accepted 2026-09-25.

`apps/server/src/mcp/` exposes exactly one module, `mcp/snippets.ts` — the snippet renderer the token and connector-setup routes (`me.tokens.snippets`, `me.connectorSetup`) render from — and nothing else. `snippets.ts` imports, by value or type, no other module under `apps/server/src/mcp/`, its runtime import closure reaches none, and its only value import is `@iridium/contracts`, so it can read no build information and no environment (D06-16). The composition root, `apps/server/src/app.ts`, is the one declared exemption: it imports `mcp/plugin.ts` to register the MCP plugin. Every other file under `mcp/` is private. The cursor codec lives in `apps/server/src/pagination/` (A35, amended 2026-09-25), and the per-credential token budget lives in `auth/tokens/budget.ts` (D04-37), so REST imports nothing from `mcp/`; `mcp/rate-limit.ts` keeps `mcpIpGate`, the process ceiling and `chargeRateLimit`, private to the mounts. 02's `mcp/` row no longer lists cursors under Owns and reads "Exposes: `mcp/snippets.ts` only (ARCH-30)".

**Enforcement.** oxlint has no `excludedFiles`, and overlapping overrides replace rather than merge, so ARCH-30 is realised through the owner table `RESTRICTED_IMPORT_OWNERS` (A6). Its row covers `apps/server/src/**`, and its only carve-outs are `DECLARED_EXEMPTIONS` entries with reasons: `apps/server/src/mcp/**` (the module itself) and `apps/server/src/app.ts` (the composition root registers the MCP plugin); the row carries no `exceptFiles`. The overrides under `apps/server/src`, each built by `restrictedImports()` so that every one carries the base families and the server set, are ordered general to specific: `apps/server/src/**` (server set and ARCH-30); `apps/server/src/mcp/**` (server set and the read-graph set of D06-15, ARCH-30 exempt); `apps/server/src/content/read/**` (server set, read-graph set and ARCH-30); `apps/server/src/pagination/**` (server set, ARCH-30 and the pagination set of A35); and `apps/server/src/app.ts` (server set, ARCH-30 exempt). The existing `config/**` and `main.ts` override sets only `node/no-process-env` and does not touch the rule.

`guards.restricted-imports.guard` enforces ARCH-30 three ways. It checks the effective configuration of every file against the owner table. Over resolved import paths it asserts that no module under `apps/server/src` outside `mcp/`, other than `app.ts`, imports by value or type a module under `mcp/` other than `snippets.ts`; that `snippets.ts`'s own imports name no other `mcp/` module and its runtime import closure contains none; and that no module outside `mcp/` imports an `mcp/` path dynamically or through a namespace import. Its in-file cases refuse a synthetic `content/read` importer of `mcp/factory.ts`, a `rest/` file importing `../mcp/tools/get-note.ts` or `../mcp/factory.ts`, `rest/plugin.ts` importing `../mcp/plugin.ts`, a synthetic `snippets.ts` importing `./factory.ts` or `../ops/build-info.ts`, a synthetic `snippets.ts` that reaches `mcp/factory.ts` through an intermediate module outside `mcp/`, `rate-limit.ts` importing `@modelcontextprotocol/server`, and a dynamic `import()` of an `mcp/` path from outside `mcp/`. Its permanent oxlint probe run refuses `../mcp/factory.ts` and accepts `../mcp/snippets.ts` from an ordinary server file, and refuses `../../mcp/factory.ts` and `../../mcp/errors.ts` from a `content/read` file, so a later oxlint or a pattern edit that changes the behaviour fails the guard. The pattern form the probe run confirms — a group glob or a regex, since oxlint's regex has no lookahead — and the reason for it are recorded in this entry by the change that lands the override.

02's module table said `mcp/` "Exposes: nothing (leaf)", yet the snippet routes are REST and the renderer sits beside the mounts whose URLs it renders; naming the one exposed module makes the rule true and checkable. Moving the cursor codec to `pagination/`, which every paginated reader shares, and the token budget to `auth/tokens/`, which both surfaces charge, removes the other two reasons anything outside `mcp/` reached into it. Reading resolved paths is independent of how many `../` an import carries, and refusing namespace and dynamic imports closes the two ways around a named-binding check. Rejected: exposing `cursor.ts` and two bindings of `rate-limit.ts` from `mcp/`; a separate MCP-exposure guard beside the restricted-imports guard; oxlint negated patterns; `exceptFiles` on the owner row.
