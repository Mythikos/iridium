# D12-20: Schemathesis milestone scope

Status: Accepted, 2026-09-17; amended 2026-09-23: the full profiles run at 250 examples rather than 500, because 500 could not complete inside a GitHub-hosted job's six-hour limit and 250 keeps the findings; amended 2026-09-24: each full profile has a 120-minute deadline and `schemathesis-full` a 270-minute job timeout, sized to a complete run's measured cost (13-decision-log.md#d12-20-schemathesis-milestone-scope-2026-09-17).

At commit `492d870`, `12-milestones.md` §5.4 explicitly requires a clean Schemathesis light run at M1. The same document's §6.2 Codegen row and §13.3 M2 row instead introduce the light lane at M2. `10-testing-and-quality.md`, under "REST — Schemathesis black-box fuzzing", defines the light profile as authenticated and stateful, with all checks and 50 examples; it defines no separate unauthenticated M1 profile. Section 1 of the milestone plan forbids later work from becoming an earlier gate.

Retain the explicit M1 exit requirement over the shipped M1 routes. The pinned light runner uses all checks and phases at 50 examples per operation against a disposable production deployment. Its principal is the seeded non-admin editor with membership in the fixture vault. Administrator credentials are used only for fixture setup and schema export; admin and test-only paths are excluded from light fuzzing. M2 extends the existing gate to its new route set rather than introducing it.

The full administrator and outsider profiles remain separate nightly coverage, at 250 examples per operation (amended 2026-09-23; the original 500 never completed a run. Measured, it took 127.7 min, paced by the fixture re-authenticating at the production login limit after the fuzzer revoked its own session 1,161 times, while 250 examples found all but one of its nine findings plus one it missed). Amended 2026-09-24: the two 250-example runs first cited at 14.0 and 32.0 min had not completed their stateful phase, which a hook error was aborting; a complete administrator profile took 54 min on a hosted runner against 9.7.2 and over 60 against 8.4.11. The owner kept 250 examples and every phase, and the budgets were sized to that cost: a 120-minute deadline per full profile and a 270-minute `schemathesis-full` job, inside the six-hour limit. Implementing those profiles early does not add their results to M1's required exit evidence. Moving light coverage to M2 would remove an explicit M1 gate; substituting an unauthenticated smoke would not exercise the authenticated API contract originally specified.

`testkit.schemathesis.unit` proves profile selection, required budgets, administrator/schema separation, rejection of an elevated light fixture, and cleanup. `schemathesis.light.contract` supplies the actual light-run evidence on both required MySQL lines. Adapter unit tests are not evidence that the authenticated run passed.
