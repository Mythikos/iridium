# A42 — Markdown preview and sanitisation pipeline: unified/remark with a custom GFM wiring, `rehype-sanitize` last, hast → React, workers

**Status:** Accepted (2026-09-11).

## Context

This is the largest single technical decision in the plan, and the digest measured it rather than guessing. Digest §7.2 verified: the unified stack is complete, MIT, ESM-only and DOM-free; `remark-stringify` does **not** round-trip source (`__bold__` → `**bold**`, `1)` → `1.`, two-space hard break → backslash), so any "edit the AST and re-serialise" design silently rewrites user content, which spec §3 forbids; micromark silently consumes a leading BOM and then reports offsets relative to the post-BOM text (off by one), while markdown-it does not strip a BOM at all and a BOM defeats frontmatter detection; `mdast` and micromark positions are UTF-16 code-unit offsets, the same unit Y.Text and CodeMirror 6 use, so offsets can address Y.Text positions directly once the stored text is BOM-free; markdown-it is 4–15× faster (100 KB: 29 ms versus ~136 ms micromark plus ~108 ms mdast build) but emits an HTML **string**, forcing a DOM sanitiser and an `innerHTML` sink, and carries no inline positions; micromark has quadratic worst cases markdown-it does not (`*a_`×20000 = 60 KB takes 13–20 s; `micromark-extension-gfm-autolink-literal` is quadratic in lines per paragraph, 40k lines = 7.7–22 s) while the **mdast-level** autolink transform is linear; `remark-gfm`'s `singleTilde` defaults to true whereas Obsidian only recognises `~~`; footnote ids get double-prefixed (`user-content-user-content-fn-1`) unless `rehype-sanitize` is given `clobberPrefix: ''`; `hast-util-to-jsx-runtime` defaults `tableCellAlignToStyle: true`, emitting inline styles that a strict CSP blocks; shiki costs 142 KB gzip for 10 languages against highlight.js's 22 KB and relies on inline styles that a sanitize-last pipeline strips; `gray-matter` (last released 2021, js-yaml 3) caches every parse keyed by the whole input when called without options — unbounded memory growth in a long-running server — and coerces `YYYY-MM-DD` into `Date`; `yaml` 2.9.1's core schema keeps dates and `yes` as strings, matching Obsidian; DOMPurify had three 2026 bypass CVEs and needs an explicit `CUSTOM_ELEMENT_HANDLING` for prototype-pollution hardening; and a per-line pre-scan costs ~4 ms/MB, cheap enough to reject pathological nesting before parsing (hast→React on a 2000-deep blockquote is 24 ms, and `mdast-util-to-hast` throws `RangeError` at ~3000). Digest §11.10 and §11.11 record the sanitiser and parser disagreements across topics.

## Decision

One isomorphic, DOM-free package `@iridium/markdown`, used identically in a browser Web Worker and in a Node `worker_threads` pool.

Pipeline: `normalizeSource` → remark-parse 11.0.0 (micromark 4.0.2) + `remarkGfmIridium` (micromark-extension-gfm-table 2.1.2, -strikethrough 2.1.0 with `singleTilde: false`, -footnote 2.1.0, -task-list-item 2.1.0 with their `mdast-util-gfm-*` counterparts, and **only the mdast transform** of mdast-util-gfm-autolink-literal 2.0.1) + remark-frontmatter 5.0.0 → mdast → remark-rehype 11.1.2 (`allowDangerousHtml: false`) → Iridium rehype transforms (github-slugger 2.0.0 ids prefixed `user-content-`, `data-line`/`data-offset` attributes, `resolveLink` → `data-link-kind`, `data-note-id`) → rehype-highlight 7.0.2 (highlight.js 11.12.0, ~20 registered languages, `detect: false`, `plainText` for dataview/query/mermaid/math) → **rehype-sanitize 6.0.0 last** with `iridiumSchema` (`defaultSchema` plus `clobberPrefix: ''`, allowed `data-*`, `span[className=/^hljs-/]`, `code[className=/^language-[\w+#.-]+$/]`, `href` limited to `http|https|mailto`, `src` limited to `http|https`, relative URLs allowed, no `style`).

Pre-scan caps per A.1. Browser: a dedicated Web Worker (comlink 4.4.2) with debounce 150 ms up to 64 KB, 500 ms up to 512 KB, 1.5 s above, and a 2 s timeout that shows a banner. Server: a piscina 5.3.2 pool of `cpus-1` with a 10 s timeout plus terminate and respawn. `@iridium/markdown-react` renders with hast-util-to-jsx-runtime 2.3.6 (`passNode`, `passKeys`, `tableCellAlignToStyle: false`) and `a`/`img`/`input`/`pre` component overrides, memoising blocks by `(startOffset, sourceSliceHash)`, with **no `dangerouslySetInnerHTML` anywhere**. DOMPurify 3.4.15 appears only at browser HTML-string sinks (print and HTML export) with an explicit configuration including `CUSTOM_ELEMENT_HANDLING`. Frontmatter is parsed with yaml 2.9.1 `parseDocument(raw, {maxAliasCount: 100, uniqueKeys: true})` on the core schema and is **never re-serialised**; `gray-matter` is banned and `remark-stringify` is banned by lint. A `PIPELINE_VERSION` bump triggers background re-projection. The XSS corpus is asserted at the hast level, in Chromium component tests, and in both web and Electron end-to-end tests.

## Alternatives Considered

| Alternative | Why rejected |
|---|---|
| markdown-it 15.0.2 | 4–15× faster and hardened against the quadratic cases, but it emits an HTML string (forcing a DOM sanitiser and an `innerHTML` sink, or an HTML re-parse into hast), carries no inline positions (blocking precise diagnostics, link resolution, and future rename tooling), and would split the codebase between a token stream for projections and a separate hast renderer. The remark costs are mitigated by worker isolation, the pre-scan caps, and the linear autolink transform. |
| shiki 4.4.3 for highlighting | 142 KB gzip versus 22 KB for the same 10 languages, ~10× the CPU, and inline `style` attributes that a sanitize-last pipeline strips and a strict CSP blocks. |
| DOMPurify as the primary sanitiser (digest Topics 4, 8) | Browser-only (jsdom on the server costs ~740 ms warm init), three 2026 bypass CVEs, and it forces an HTML string through an `innerHTML` sink. `rehype-sanitize` on hast is the security boundary and runs identically on client and server. |
| `remark-gfm` 4.0.1 as a black box | Enables the quadratic micromark autolink extension and defaults `singleTilde: true`, which misreads Obsidian-authored `~one~`. |
| `gray-matter` for frontmatter | Unbounded parse cache in a long-running server, js-yaml 3 date coercion, and it treats an unterminated `---` at file start as frontmatter-to-EOF, silently swallowing a note body. |
| Any AST → Markdown serialisation step (for renames, link rewriting, or frontmatter edits) | `remark-stringify` rewrites source; spec §3 forbids rewriting content merely by opening or editing. All mutations are text edits on Y.Text driven by mdast offsets. |
| Parsing on the Node main thread | A 1 MB note costs 3–5 s and `*a_`×20000 costs 13–20 s, which would stall every WebSocket on the process. |
| Inheriting `rehype-sanitize` defaults | Default `href` protocols include `irc`, `ircs`, and `xmpp`; the policy is stated explicitly instead. |

## Consequences

Positive: one AST serves preview, projections, the import report, and the link index; the security boundary is one function that runs on both client and server and is tested with a corpus at three levels; no inline styles and no `innerHTML`, so a strict CSP holds; mdast offsets address Y.Text directly, which is what makes offset-based formatting commands and `data-line` scroll sync possible. Negative: remark is materially slower than markdown-it, which is why the worker isolation, the caps, and the debounce tiers are not optional and why the switch criterion is recorded (p95 preview > 100 ms at the pilot p95 note size after mitigations); highlight.js registers a fixed language list, so an unlisted language renders unhighlighted (deliberate — auto-detection is costly and mis-guesses); `PIPELINE_VERSION` means a dependency upgrade can trigger a full re-projection job.

## Verification

`markdown.commonmark.unit` (CommonMark 0.31.2 example suite through remark-parse); `markdown.xss-corpus.unit` (hast level, Chromium component test, web E2E, Electron E2E — `javascript:`/`data:`/`vbscript:` URLs in links, images, definitions and autolinks; raw HTML; event handlers; SVG and MathML; DOM-clobbering ids and names; CSS injection); `markdown.pathological.unit` (each pre-scan cap rejects with a diagnostic instead of crashing; worker timeout and respawn); `markdown.golden.unit` (source → mdast JSON → hast JSON → HTML fixtures committed in the package, including the footnote case: no double `user-content-` prefix and hrefs matching ids); `markdown.frontmatter.unit` (BOM, CRLF, `yes`, dates, alias bomb, duplicate keys, unterminated block); `markdown.no-rewrite.prop` (parsing or previewing never mutates the source, and `project(parseNote(src)).markdown === normalizeSource(src).text`; the `remark-stringify` and `gray-matter` import bans are lint rules in the `static` job); `markdown.offsets.prop` (mdast offsets map onto the stored Y.Text string exactly); the preview-render budget of `perf.workspace.e2e` (p95 < 100 ms for a 100 KB note).
