# D14-04: question encoding and the one question record

Status: accepted; amended 2026-09-25: `14-risks-and-open-questions.md` §G is the one record of every question, answered and open, and a commit rather than a pull request encodes an answer.

**As accepted.** Every question's working default is encoded as a named flag, constant, CI lane or reserved column, never as an implicit assumption in code; when the question is answered, the encoding is inverted or removed in the same commit as the decision, and the row moves to `docs/answered-questions.md` carrying the owner's words, the reading applied and the pull request that encoded it. A question raised after the eight were answered is minted as a new `G<n>` and must be answered before the 1.0 tag.

**Amended 2026-09-25.** The questions have one record, `14-risks-and-open-questions.md` §G. Its answered table carries, for each question, the owner's words, the reading applied, where each consequence lives and the commit that encoded the answer (the pull request once the owner restores that workflow), written in by the follow-up docs commit because a commit cannot name itself; G1–G8 cite the plan revision that encoded them before M0. Its open table carries each question raised after 2026-09-12 with the date it was raised, its due cell, its working default and the named encoding of that default, and the recommendation. The due cell names both the milestone entry that needs the answer and the exit rehearsal at which the register check enforces it: the check fails an open row once the effective test target (`IRIDIUM_TEST_TARGET_MILESTONE` when set, otherwise CURRENT, the last exited milestone) reaches the due milestone, which first happens at that milestone's exit rehearsal, and it fails any open row at the 1.0 tag. The entry obligation is procedural and is carried by the milestone's Dependencies section and the previous exit record's Open questions field. If the entry passes unanswered, D12-7 applies: the default stays, the alternative becomes post-MVP, and before the exit the row moves to the answered table with the default recorded in place of the owner's words. An answer moves its row from the open table to the answered table in the commit that inverts or removes the encoding. `docs/answered-questions.md` and `docs/open-questions.md` are withdrawn.

The register check D14-02 names reads 14 §G: every `G<n>` a risk references is in one of the two tables, with the owner's words and the reading applied when it is answered; an open row fails once the effective test target reaches its due milestone; and no row is open at the 1.0 tag. G13, raised 2026-09-24, is the first open row: its answer is due at M4 entry and CI-enforced at the M4 exit rehearsal, and its working default is encoded by AG9's sign-in surface.

One record per fact is the codebase's rule. 14 §G already carries the owner's words, the reading and the consequences, so a parallel `docs/answered-questions.md` would be a hand-copied duplicate, and `docs/open-questions.md` was never created. The check keys on the effective test target, which reaches M<N> only at the M<N> exit rehearsal; a check keyed on CURRENT + 1 would turn the previous milestone's exit-record commit red, although that record lists the open question by design, so CI enforces at the latest safe point and the entry obligation stays procedural, as D12-7 has always worked. Commits are the encoding unit while main is worked without pull requests (owner instruction, 2026-09-19). Rejected: creating `docs/answered-questions.md` as a second copy of 14 §G; keying the open-row check on CURRENT + 1.
