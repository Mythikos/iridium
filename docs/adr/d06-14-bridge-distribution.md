# D06-14: bridge distribution

Status: accepted; amended 2026-09-25: the server image carries the bridge and serves it from M3, with a verified banner version, a `302` latest alias and a `SHA256SUMS`; the desktop copy follows at M5. The operational half is [OPS-65](./ops-65-bridge-download.md).

**As accepted.** Bridge distribution: one build artefact, `dist/iridium-mcp.mjs`, published both as `resources/bin/iridium-mcp.mjs` in the desktop package and as `GET /desktop/tools/iridium-mcp-<version>.mjs` with a `latest` alias and a published SHA-256; `release.yml` asserts the two copies are byte-identical. The `.mjs` extension is part of the contract because the Claude Desktop snippet runs the file as `node <path>`; `iridium-mcp` is the package's `bin` name only.

**Amended 2026-09-25.** The one artefact is still `dist/iridium-mcp.mjs`, and its second line is `// iridium-mcp <version>`, written by its own build from its manifest; it inlines every dependency (tsdown's `deps: {alwaysBundle: [/.*/]}`, only `node:` builtins external, no chunk file) and carries no sourcemap. The server image builds it once, in stages based on `FROM --platform=$BUILDPLATFORM ${NODE_IMAGE}` (a stage based on another stage would inherit the per-target platform), and carries it read-only at `/app/tools/iridium-mcp.mjs` with `IRIDIUM_TOOLS_DIR=/app/tools`. When `IRIDIUM_TOOLS_DIR` is set, the server requires a non-empty regular `iridium-mcp.mjs` there whose banner version equals its own, and otherwise exits 2 (`config.tools_bundle_missing`, `config.tools_bundle_version_mismatch`); `iridium config check` applies the same check, so the served name is verified, not assumed. The server holds the file in memory and serves exactly three names at `/desktop/tools/`, public and hidden from OpenAPI, with an empty `404` for anything else: `iridium-mcp-<serverVersion>.mjs` as `application/octet-stream` with an attachment disposition, a strong `ETag` equal to its SHA-256, `Cache-Control: public, max-age=60` and `304` on a matching `If-None-Match`, never `immutable`; `iridium-mcp-latest.mjs` as a `302` with `no-store`; and `SHA256SUMS` in the `/desktop/updates` `SHA256SUMS` format and headers. `release.yml › bridge` (M3 and later) extracts the file from both platform images of the release digest, asserts they are identical and carry the release version, runs `bridge.parity.contract` in container mode against that digest with the extracted file, from a scratch directory outside the workspace so module resolution cannot fall back to the repository's `node_modules`, checks that `SHA256SUMS` and the `ETag` equal its hash, and publishes it. The desktop package (M5) copies that release artefact into `resources/bin/iridium-mcp.mjs`, and `release.yml` asserts byte identity.

The bridge shares the product version, so a server of version X serving the bridge of version X needs no compatibility matrix — but only if the served file is checked, which the banner makes possible without running it; extracting from both platform images makes "one artefact, the same bytes everywhere" a checked property of every release, and serving it from the image makes the download live at M3 rather than waiting for the desktop package. Rejected: trusting an operator's file unchecked; deferring the download to M5; year-long immutable caching of the version-named file.

Source: the D06-14 amendment in [the decision log](../plan/13-decision-log.md), and D06-14 in [06-mcp-and-agent-access.md](../plan/06-mcp-and-agent-access.md), "Decisions made in this section".
